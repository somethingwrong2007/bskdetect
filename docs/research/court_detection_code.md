## 0. 结论先行

1. **篮球专项、许可证干净、可直接引入的"现成标定代码 + 权重"基本不存在。**
   唯一篮球专项的公开框架 KaliCalib 是 **CeCILL-2.1（强 copyleft，GPL 兼容）**；
   DeepSportRadar 官方基线仓库**没有 LICENSE 文件**（默认保留所有权利）；SoccerNet 系（sn-calibration 无 LICENSE、
   sn-gamestate 为 GPL-3.0）、足球的 PnLCalib（GPL-2.0-or-later）同样不可引入代码。
   → **推荐：只用思路，不引入代码**（第 6 节给出"若将来出现合规实现"的封装预案）。

2. **我们现有路线（多类线分割 + 四角参数化 + chamfer/Powell + 时序中值）方向正确，且比多数公开方案更贴合"转播平移/变焦"场景。**
   外部方案多数假设**固定机位**（Keemotion 场馆相机）或**整场可见**，其权重对我们的镜头运动没有增益；
   真正值得吸收的是**几何约束**与**多线索融合**，而不是换模型。

3. **四个最值得落地的改进（按性价比排序）：**
   - **点位约束补线约束**：从分割掩码提取"线交点"（边线×罚球线、边线×三分线），把交点作为强点约束加入代价（DeepSportRadar 基线、KaliCalib 的共同做法）；
   - **相机模型约束焦距**：用两组正交线族的**消失点**估焦距先验，压掉"平面点标定焦距病态"的自由度，显著改善变焦段的稳定性；
   - **时序从"角点中值"升级为"预测 + 残差门控"**：变焦/推拉时中值会滞后，需按帧间尺度变化自适应衰减历史（现 `cut_frac=0.22` 只在切镜时清空）；
   - **ROI 剔除改用"脚点 + 球场坐标系 + 米制余量"**：现 `server_rt.py`/`crowd_filtering.md` 用 bbox 中心的像素矩形，
     在斜视角下会误删底线附近球员、漏删替补席前排。

4. **数据方面：没有任何"可商用再分发"的篮球场关键点/线数据集。**
   DeepSportRadar 篮球数据集是 **CC BY-NC-SA 4.0（禁商用）**；TennisCourtDetector 的数据来自 YouTube 抓帧；
   Roboflow Universe 上的篮球场关键点数据集许可需逐个页面核实（默认常见 CC BY 4.0，但不能假定）。
   → **继续走自造合成数据是对的**，重点应放在"域差压缩"而不是"找数据"。

## 1. 我们的现状基线（对照用）

| 环节 | 实现 | 关键事实 |
|---|---|---|
| 球场几何真源 | `bsk/court.py` | FIBA 28×15 / NBA 28.65×15.24 / 3x3 15×11，米制、原点在中心 |
| 线分割 | `bsk/calib_seg_net.py` | MobileNetV3-small 编码器 + 轻量解码器，6 类（背景/边线/三分/漆区/中线/中圈），输入 384 |
| 合成数据 | `bsk/calib_seg_real.py` | 3D 渲染线层贴到真实转播背景，多机位/多地板色/遮挡带，真实白结构标 ignore |
| 单应拟合 | `bsk/line_calib.py` | 双初始化（边线 Hough 线族 4! 枚举 + 漆区四边形），chamfer 截断均值（召回）+ 外框距离中值（精确率），四角 Powell 精化 |
| 时序 | `CalibrationTracker` | 每 K=10 帧拟合、近 5 次角点中值、单帧失败沿用 ≤2s、切镜清历史（`cut_frac=0.22`）、后台线程不阻塞帧路径 |
| 合理性校验 | `Calibration.is_plausible` | 面积占比 5%~160%、跨度、凸性、角点不全在画面外 |
| 失败兜底 | 全链路 | 标定不可信 → 关闭剔除，宁可不删 |

结论：这套设计在"**线是唯一可靠线索、角点常被裁掉/遮挡**"的转播场景下是对的；
公开方案里主流的"关键点热图 + DLT"恰恰依赖角点可见，直接搬会退化。

## 3. 逐类拆解：它们的做法与我们差在哪

### 3.1 线分割 + 几何（我们、DeepSportRadar 基线、PnLCalib、TVCalib）

- **共同点**：都承认"整条线可见性远好于角点"，用线做主要证据。
- **DeepSportRadar 基线**：把 20 条线分成 20 个语义类，**求交**得到 2D 点，匹配到 FIBA 3D 角点，再 `calibrateCamera`。
  关键经验：**交点不足时要有显式降级**（它回退到训练集平均相机参数；我们回退到"不剔除"——我们的降级更安全）。
- **TVCalib / PnLCalib**：不做"线 → 点 → DLT"的两段式，而是**直接在相机参数空间优化线到线距离**。
  对我们最有价值的一点：代价函数应**按线段/按类归一化**，而不是全局 chamfer 均值——否则一条边线（像素多）会压过中圈（像素少）。
  我们现在的 `CLASS_W` 只是加权，未做"按该类可见像素数归一化"，长线仍主导。
- **差距**：我们缺"线交点"这一层。交点是**零成本的强约束**（同一份掩码即可算），且对"线族赋值歧义"有天然消歧作用。

### 3.2 关键点 / 热图（KaliCalib、CourtKeyNet、TennisCourtDetector）

- **KaliCalib**（CeCILL-2.1）：编码器-解码器回归关键点位置，配"透视感知的关键点采样"、篮筐位置回归辅助任务、重数据增强。
  在 MMSports 2022 挑战赛上 MSE 107.78mm（test）/ 73.16mm（challenge）——注意其训练/测试都是 **Keemotion 固定场馆相机**，
  不是转播推拉镜头；这个数字不能直接对标我们的场景。
- **TennisCourtDetector**：热图之后接**经典 CV 精修**（裁块 → 提白像素 → 拟合线 → 求交），再用**单应一致性**把偏移点拉回参考位置，
  中位误差从 2.83px 降到 1.83px。这条"**网络给初值、几何做精修**"的路线，正是我们现在的 `line_calib` 在做的事（只是我们反过来：分割给线、优化给位姿），
  说明精修层的价值已被独立验证。
- **结论**：不建议把主路径换成关键点热图。角点在转播中经常出画（尤其底线机位、近景），而我们的输入是**掩码**，信息量更大。
  但可以**加一个轻量关键点/交点头作为辅助监督**（多任务），帮助分割网络学到"线的端点/拐角"。

### 3.3 端到端回归 H / 图像检索

- **Chen & Little 2019**：3 自由度相机姿态引擎批量渲染边缘图 → Siamese 特征-姿态库 → **检索初值** → 截断距离图精化。
  这条"检索 + 精化"与我们"多初始化 + Powell"结构同构，说明**初值质量决定上限**；我们可以把"检索"换成"上一帧 H + 尺度搜索"（更省）。
- **HomographyNet 类**：单图直接回归 4 点偏移。自由度 8，纯回归在"线大面积缺失"时不可控，且无法给置信度。
  只适合作为**多初始化候选之一**（成本低，失败可丢弃）。
- **全端到端（图像 → H）在转播场景的已知失败模式**：变焦后尺度先验失效、镜头切换后无状态、无几何可解释性 → 无法做"可信度门控"。
  我们现在的 `is_plausible` + 代价阈值正是端到端方案缺的东西，不应放弃。

- 代码仓库与数据是**两套许可**：数据 CC BY-NC-SA 4.0，代码仓库有的有 Apache-2.0（如 `instance-segmentation-challenge`），

- 即便只做"研究对照"，把其权重或派生权重放进 Apache-2.0 仓库，也存在**许可冲突与再分发风险**。

### 4.3 自造合成数据的注意点（对应 `calib_seg_real.py`）

现状已经做得比较到位（真实背景贴图、地板贴合、遮挡带、ignore 标签）。结合本次调研，补充几条：

1. **标签语义一致性**：贴真实背景时，背景里"未标注的线"必须确保被地板完全覆盖或标 ignore——否则网络学到"有些线不该预测"。
   现在用 ignore(255) 处理，方向正确；建议加一条自检：合成图上"非 ignore 区域内的真实白线像素占比"统计，超阈值样本丢弃。
2. **域差的主要来源不是纹理而是"镜头"**：转播的推拉、长焦压缩、浅景深、运动模糊、字幕条遮挡，合成里几乎没有。
   建议显式加：**变焦序列**（同一机位连续多档焦距）、**运动模糊核**、**底部字幕/记分条遮挡**（转播固定出现在底部）。
3. **关键点/交点的标签**：合成渲染器已知相机参数，可**零成本导出交点坐标**（边线×罚球线等），为"交点辅助监督"准备标签。
4. **机位分布要对齐真实转播**：现有分档（全景/半场/近景/底线/高位）合理；建议按真实素材统计各档占比后重采样，避免"全景过多"。
5. **负样本与难样本**：纯地板/纯观众席负样本已有 8%；建议补"只有中圈可见"、"只有一条边线可见"的极限样本，直接对应失败模式。

## 5. 与现方案的差异与改进建议

### 5.1 优劣对照

| 维度 | 现方案（线分割 + 四角拟合） | 关键点方案（KaliCalib 类） | 端到端 H 回归 |
|---|---|---|---|
| 角点出画/遮挡 | **强**（线任一段可用） | 弱（角点不可见即失效） | 中（靠数据覆盖） |
| 变焦 | 中（拟合可重跑，但中值滞后） | 中 | 弱（尺度先验易失效） |
| 可解释性/门控 | **强**（chamfer 代价 + 几何校验） | 中 | 弱 |
| 实现/训练成本 | 已投入 | 需重训 + 标注 | 需大量数据 |
| 精度上限 | 受"四角参数化"限制 | 受关键点定位精度限制 | 受数据分布限制 |

**判断：不换主路径。** 现有方案的结构性优势（遮挡鲁棒、可门控、可解释）恰好是转播场景最需要的。

### 5.2 建议 1：线交点作为点约束（性价比最高）

- 从 6 类掩码里提取交点：`boundary × paint`（罚球线端点）、`boundary × three_point`（底角三分与边线交点）、`boundary × center_line`。
- 每个交点给一个 2D 位置 + 不确定性（用掩码距离变换的局部极小值 + 线方向夹角，夹角越小越不稳）。
- 代价里加一项：`Σ w_i · ρ(‖proj(H, P_i^world) − p_i^pix‖)`，`ρ` 用 Huber。
- 预期收益：给"线族赋值歧义"提供消歧（错误赋值下交点位置会明显偏），并抑制"整体平移一点也差不多"的退化解。

### 5.3 建议 2：消失点 → 焦距先验（针对变焦）

- 边线族（长边）与端线族（短边）在像平面各有一个消失点 `v1, v2`；正交线族满足 `(v1−c)·(v2−c) = −f²`（`c` 主点，可用图像中心近似）。
- 用 RANSAC 拟合两组线后估 `f`，作为**软先验**加入拟合（`|f − f_prior|` 惩罚）或直接用来筛候选。
- 为什么重要：**纯平面点/线标定焦距是病态的**（DeepSportRadar 基线用 `calibrateCamera` 也有此问题）；
  有了 `f` 先验，H 的 8 个自由度实际被压到 6 个左右，变焦段的抖动和"缩到一小块"的退化解会明显减少。
- 实现成本低：`cv2.findHomography` 之外只需几十行线拟合 + 消失点求解，无外部依赖。

### 5.4 建议 3：时序从"中值"升级为"预测 + 残差门控"

现状：`CalibrationTracker` 每 10 帧拟合，近 5 次角点取中值，切镜（>0.22·对角线）清空，陈旧 ≤2s。

问题：**推拉/变焦时 5 次中值会滞后**（相当于把 0.3–0.5s 前的尺度平均进来），表现为"ROI 多边形比画面慢半拍"。

建议：
- 用上一帧 H 预测当前四角（对角点做 2D 匀速外推，或对 H 做 `H_t = H_{t-1} · S` 的尺度/平移模型），
  把"预测值"作为 Powell 的初值之一（现有初值全是几何枚举，缺"上一帧"这一路）；
- **残差门控**：若本次拟合与预测的角点差 < 阈值，则用**指数滑动平均（按残差自适应 α）**而不是中值——变焦时可快速跟上；
- 切镜检测保留现有 `cut_frac`，并补一条"画面尺度突变"（掩码线像素总长突变 > 40%）作为并行触发。

### 5.5 建议 4：多初始化的赋值歧义

现状已枚举 4! 种"图像线 ↔ 世界矩形边"对应。可再加两类候选，成本很低：
- **上一帧 H**（热启动，见 5.4）；
- **消失点排序**：按消失点把线分成两族，族间对应关系由消失点方向决定，天然把 4! 降到 2 种；
- 候选打分顺序保持"chamfer 粗排 → 前 K 个精化"，避免候选爆炸。

### 5.6 建议 5：代价函数按类归一化

- 现状 `CLASS_W` 是固定权重，chamfer 用"截断均值"（对遮挡友好）。
- 建议改成 `Σ_c w_c · (Σ_{p∈c} ρ(d(p)) / max(1, n_c^visible))`，其中 `n_c^visible` 用该类**预测可见**的采样点数量估计
  （可由 H 判断该线段是否在画面内），避免长边线压过中圈；
- 精确率项（boundary 点到投影外框距离中值）保留，它是防"缩成一小块"的关键，不要动。

### 6.2 预案：若将来出现"MIT/Apache 篮球标定实现或权重"

最小侵入封装（不改现有 `line_calib` 主路径）：

```
bsk/calib_ext/__init__.py        # 适配层：fit(rgb)->Calibration，失败返回 None
bsk/calib_ext/model.py           # 第三方模型（保留原版权头 + 文件级许可声明）
bsk/calib_ext/weights/           # 不入库；运行期从 data/models/calib_ext/ 加载
NOTICE                           # 第三方组件与许可全文
docs/research/court_detection_code.md  # 本文件的"引入记录"章节
```

集成规则：
- **只做 fallback**：仅当自有拟合返回 None 或代价超阈值时调用；自有结果始终优先，避免被外部域偏置带跑；
- **实时预算**：外部模型推理 ≤ 8ms/帧（960 宽）、只在 `every=10` 帧的拟合槽里跑，且在现有后台线程内，
  不进入帧路径；超预算直接跳过本轮（不排队）；
- **强制门控**：外部结果同样过 `Calibration.is_plausible` + 代价阈值 + 时序中值，禁止直出；
- **A/B 可回滚**：开关 `BSK_CALIB_EXT=0/1`，默认 0；上线前用现有 `eval_pose_3d.py` / 标定叠加图做对照。

### 6.3 风险清单

1. **许可传染**：CeCILL-2.1 / GPL 代码一旦混入，整个 Apache-2.0 仓库的再分发会被质疑；即便是"复制几十行"，也构成 derivative。
2. **权重污染**：用 CC BY-NC-SA 数据训练的权重，即使代码 MIT，权重本身也不能商用/再分发；且 SA 条款对"派生作品"的界定有争议。
3. **来源不明数据**：YouTube 抓帧、转播截图二次标注（TennisCourtDetector、Kaggle 850 张）——著作权与肖像权双重风险。
4. **域不匹配导致的"假提升"**：Keemotion 固定机位权重在我们的推拉镜头上可能反而更差；必须 A/B，不看论文数字。
5. **维护成本**：第三方模型与我们的 6 类线定义、坐标系约定（`H=pixel→court`）不一致，适配层是长期负担。
6. **实时预算挤占**：现有链路 20–30ms/帧已经比较紧，任何新增推理都要走后台槽位。

## 7. "球场范围剔除"的工程做法（建议）

### 7.1 现方案的问题

`docs/crowd_filtering.md` 的 Filter 4 用 **bbox 中心** + **像素矩形** 判断是否在球场内。这在斜视角下有两类系统性错误：

- **误删底线附近球员**：球员贴底线时，bbox 中心可能落在底线外侧（尤其人被拉长、或半身出画），被当作观众删掉；
- **漏删替补席前排**：替补席常紧贴边线，bbox 中心可能"压线"落进矩形内。

另外，矩形是"轴对齐像素框"而非真实投影四边形，斜视角误差更大。

### 7.2 推荐做法（几何稳健版）

1. **在球场坐标系里判内外，而不是像素里。**
   把检测点用 `H`（pixel→court）投到米制坐标，再与 `[-hl−m, hl+m] × [-hw−m, hw+m]` 比较。
   好处：余量 `m` 用**米**表达，天然随变焦缩放；判定与画面几何无关。
2. **用"脚点"而不是 bbox 中心。**
   优先：踝关节中点（`pose_filter` 已有 17 点）→ 退化到 bbox 底边中点 → 再退化到 bbox 中心。
   脚点才是"人站在地面的位置"，这是单应唯一严格成立的点。
3. **非对称余量（关键）。**
   - **删**的条件要严：脚点在 `m_out = 0.3~0.5m` 之外才删；
   - **留**的条件要松：脚点在 `m_in = 1.0~1.5m` 之内一律保留；
   - 中间灰区：**保留**（宁可不删）。
   这样"边线附近的裁判/替补"不会被误删，而看台/记分台（通常 >2m 外）稳定被删。
4. **按边线分别估余量。**
   近端边线常被观众遮挡 → H 在该侧的误差更大。可用每类线的 chamfer 残差给"该侧余量"加成
   （例如残差 > 3px 的边，余量 ×1.5），避免"一刀切"。
5. **裁判不是"观众"，不要把裁判塞进剔除逻辑。**
   裁判在界内、尺寸与球员相同；现有"保留裁判"的选择是对的。
   若要区分，走队伍/球衣分类（`docs/jersey_number_detection.md` 的延伸），不要用位置规则硬切。
6. **降级阶梯（保持"宁可不删"）**：
   `H 新鲜（<2s）且 plausible` → 正常剔除；
   `H 陈旧` → 只删"明显远离球场"（米制距离 > 3m）的检测；
   `H 缺失/不可信` → 全保留。
7. **可视化验收**：每次剔除把"球场多边形（含余量）+ 被删框"叠到图上（现有叠加图机制可复用），
   人工按"误删率"验收，而不是只看"删了多少"。

### 7.3 与 3D 提升的关系

- 场地平面上的 3D 提升只需要 H；ROI 剔除与 3D 提升应共用**同一份 H 与时序状态**，避免两处各自拟合导致不一致；
- 球员"是否在界内"用米制坐标判断后，可直接复用为"出界"事件的特征，不必另做一套。
